# Separate scorecards 1.0.0

Task TASK-000004; REQ-000031 and REQ-000032. `scorecards.py` exposes `scorecards(organization, projects, measurement_health)` with no external dependencies. It never produces an opaque composite quality score, LLM-derived labels or inferred cost/model values. Return sections are organization, projects keyed by explicit immutable project ID, and measurement_health. Input observation_kind/source provenance should be supplied in measurement_health to distinguish fixtures, observed native agents and production.

Organization input is a list of explicit observations, with failed attempts/retries represented rather than filtered out. Every binary rate discloses its observed denominator and total rows for coverage; missing values are excluded as unknown, never converted to false/zero. Routing uses independently labeled expected_route vs actual_route; unlabeled cases disclose missing coverage. Delegation acceptance uses explicit delegation_attempt rows. Rework remains a separate rate. task_class/configuration groups disclose acceptance, latency, observed cost and accepted comparable outcomes per observed cost; unknown model/reasoning stays unknown, and absent resource telemetry cannot establish free work.

Planning reports requirements_covered/requirements_total, unauthorized_deviation, and explicit replan_cause. Handoff_complete and independent recovery_resumed are separate rates: filled fields do not establish actual resumption. retained_scenario_failed retains its scenario denominator. No short-plan reward or cross-task-model winner is inferred.

Projects maps project ID to explicit observation lists. Reported dimensions are requirement_satisfaction, correctness, security, reliability, maintainability, escaped_defects, delivery_efficiency, rework and user_acceptance. Dimension bool/null describes observed presence/satisfaction according to that project's pinned test contract; escaped_defects and rework true mean those events occurred. Missing project dimensions have null rates. Keep each project's authoritative tests and units with its observations; never aggregate across projects to hide failures. Production delivery metrics come only from the explicit DORA service registry/calculator.

Measurement health is an independent caller-supplied report, copied without invention: include missing/invalid events, broken links, absent provenance, unknown model/tokens/cost, expected/instrumented/unobserved coverage and denominators. The instrumentation coverage_report and DORA measurement_health provide compatible source reports. Null values remain null. Separate scorecards describe observed samples and coverage rather than granting acceptance; hard authority/evidence/test/security/review/traceability gates remain independent in quality-gates/improvement.py.
