# Versioned append-only event ledger

Import `instrumentation.events.EventStore(path)` with `agent-org/factory` on Python's path. `append(event)` returns `{appended,event}`. Exact duplicate envelopes are idempotent; changed duplicates fail. `read_events(as_of=None)` verifies the entire ledger then filters ingestion times inclusively. `snapshot(as_of=None)` binds the exact retained rows with SHA-256; late occurrence times never change an earlier ingestion snapshot.

Required envelope: `schema_version:1`, `event_id:EVT-000001`, `event_type` lower-case identifier, `task_id:TASK-...`, `run_id:RUN-...`, `agent_id:AGENT-...`, `classification:organization|project|cross_boundary`, UTC `occurred_at` and `ingested_at` ending `Z`, and `data:{}`. Optional `causal_event_ids` must identify already-appended events. Unknown schema/envelope fields fail. Data keys use the documented `SAFE_DATA` whitelist in events.py; strings are bounded and obvious credential patterns rejected. This is a conservative metadata filter, not a comprehensive secret detector: never supply secrets, raw prompts, file contents or command output. Model/token/cost unknowns are null.

Ledger adds `sequence`, `previous_hash`, `hash`; the hash covers canonical sorted compact UTF-8 JSON excluding `hash`. Sequence starts at one. A local POSIX flock serializes validated append/read; flush and fsync finish append. Writer validates existing bytes before mutation. Missing final newline, corrupt JSON/hash/sequence, missing causal links or duplicate identity reject further use with bytes preserved. No silent tail repair: preserve/quarantine damaged ledger, reconcile external evidence, explicitly record the lost interval and establish a new ledger under authorized recovery. A different file is a different chain.

Corrections append `event_type:correction`, `data:{target_event_id,reason,replacement}` with the target in `causal_event_ids`. They preserve originals; consumers apply their own versioned correction rules to immutable snapshots. Ledger validates linkage and replacement metadata shape, while domain adapters validate the replacement's domain schema. DORA uses an independent normalized domain schema; adapters map envelope data explicitly and preserve provenance. No implicit aliasing of event types/payloads.

Retain 180 days, then explicit reviewed archival preserving accepted snapshots. No automatic deletion. Concurrent same-user malicious rewriting can recompute the entire chain: no external trusted anchor is installed. Locking is local advisory file locking, not a distributed task claim lock. Callers own safe parent-directory paths and must not rename/replace an active ledger.
