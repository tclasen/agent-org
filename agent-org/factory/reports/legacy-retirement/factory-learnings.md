### Local lean factory decisions, failures and bounded acceptance

The older `old/work/factory` is a separate implementation/history from `old/factory`. Its final lean review claims R01–R18 locally accepted within a reduced one-owner/Pi/database scope, with a deliberately accepted blocked-recovery limitation. That is a historical source claim, not current organizational acceptance or production certification. Earlier broader multi-adapter/full-stack documents remain historical, superseded for that MVP. [F14–F15]

1. **Quiescent capture:** ending the model or exec stream leaves detached writers. Terminate/observe the actual agent container before a separate read-only capture container exports its workspace; bind Pod/container identity before/after; keep expiry and worker lease. Delete the Pod too early and emptyDir data is gone. Export bounds were60s/100MiB with no deadline extension. [F16]
2. **Independent reproducibility of a patch:** restore immutable base, apply only the verified returned patch to a fresh third tree and run trusted independent assertions in a credential-free deny-all gVisor verifier. Repository-authored tests cannot substitute. Memory-backed1GiB trees compete with execution inside4GiB; aggregate tmpfs sizing is not a promise arbitrary workloads fit. [F17]
3. **Cleanup proof before slot release:** API object absence can coexist with runtime processes/mounts. Read-only dedicated-node proof binds UID/machine/boot, CRI records/process cgroups/kubelet paths/mounts and exact allowed persistent-database identity. Unknown observations retain occupied capacity. Recreated same-name resources are not adoptable identities. [F18]
4. **Write-ahead attempt fences:** setting attempted=true at queued→provisioning prevented safe recovery of failures before any actual Pod permission. Schema38 moved arming to an audited callback after input/node/network validation and before first Pod observation/create. Historical true markers stay true. A false durable marker plus exact absence/node proof enables never-attempted cleanup; no UID is invented. [F19]
5. **Accepted availability cost:** an armed attempt whose actual Pod UID is unavailable can remain reserved indefinitely. Fence account/run access and preserve unknown model use; the procedure never clears capacity or fabricates cleanup. The source says the user accepted this bounded MVP limitation; the present organization has not thereby accepted it. [F14,F19]
6. **Audit coupling:** restricted database functions serialize append/version/capacity changes with mandatory audit; failed/suppressed/full audit must roll back the effect. Hash chains are covered-change detectors, not tamper-proof storage. Service login binding survives role selection and leases fence reporters, not previously accepted packets. [F20–F22]
7. **Durable metrics:** the earlier Prometheus restart fixture lost an accepted source sample after remote-write outage/replacement even with retained PVC and historical queries. Replay log messages did not prove delivery. The source investigated but did not adopt Alloy; scanner discovery initially missed non-executable files. Later lean MVP replaced the deferred collector stack with a bounded durable database path. Preserve both failure and resolution scope. [F15,F23]
8. **Physical cleanup and quotas:** database/payload deletion must be confirmed physically with guarded receipts; declared PVC capacity is insufficient. The runtime probe hit ENOSPC at55,988,224 bytes on a64MiB backing filesystem and fork exhaustion at253 children under256 RLIMIT_NPROC, then recovered. An unprivileged mount check initially failed cleanup; privileged observation/loop release corrected it. [F15,F24]
9. **Absolute deadlines:** relative kubelet deadline could gain20s after stale construction time. Independent container helpers must enforce original absolute expiry, join resistant children and reject expired recreation; API-outage behavior remained unqualified. [F14,F19]
10. **Update coherence:** source/schema/image/helper/backup compatibility and installed qualification must advance together. Stop/join old host, keep admission disabled during migration, fail closed against missing functions and preserve original retention clocks. A source-only passing gate is not an installed upgrade. [F14,F19,F25]

## Taxonomy proposals and agent-organization lessons

The two intentionally untracked collaboration/handoff documents are conceptual proposals, explicitly not an adopted taxonomy, baseline or validated industry standard. Their combined model separates work type, domain, autonomy, authority, context/consequences and assurance. Sixteen provisional work labels cover research/discovery; knowledge stewardship; analysis/diagnosis; forecasting/simulation; strategy/planning; design/specification; software/computation; content/media; translation/adaptation; evaluation/assurance; adjudication; advice; teaching; case/transaction work; coordination/relationships; monitoring/response. A factory composes several types. Eleven candidate control families remained open; activity permissions and concrete risks determine applicability, rather than a domain or work label automatically fixing risk. [F62–F63]

Preserve the useful distinctions: delivered learning materials are not demonstrated learner improvement; a response is not a resolved case; a prepared agreement is not authority to send/accept/sign it. Autonomy describes independent planning/action; authority names permitted reads/writes/publication/commitments/spending/delegation. Both may vary by activity. Conceptual profiles should identify accountable owner, inputs/artifacts/consumers/outcomes, workflow/dependencies/persistent state, limits/escalation, sensitivity/scale/reversibility and acceptance/recovery evidence.
