## Transferable lessons

**L1 — An evaluated process can be slower and still fail more often.** The work screens preserve negative skill effects, local timeouts, cell regressions and inadequate utility evidence despite valid native records (S01–S02). The source's initial no-workflow skill pairs show a descriptive −10.5 percentage-point primary delta and 1.34 median latency ratio; these are one-repeat mixed-task observations. Recommendation: qualify a current-organization change on accepted complete outcomes, human correction burden and resource coverage using matched independent trials. A valid schema or a small aggregate gain is insufficient. Verifier: retain baseline/candidate pairs, per-cell losses, fixed outcome rubric and missing-usage counts. Confidence: high for the recorded limitations; no general claim that skills help or hurt.

**L2 — Evaluate the evaluator against valid alternatives and actual wrong behavior.** Competition documents undeclared row-wrapper requirements (L005), alert-count versus message-content confusion (L027), zero selected tests incorrectly accepted as a negative control (L034), Unicode/CRLF/whitespace contracts, observer regex false positives (L070) and outcome attribution before a terminal result existed (L073). Work shows unstated precision and schema assumptions (S01–S02, S07). Recommendation: freeze semantic contracts, prove correct implementations pass and genuine defects fail, require positive executed-test counts and retain post-hoc corrections without rewriting the primary endpoint. Verifier: valid alternative layouts/schemas and deliberately wrong candidates against the complete consuming evaluator. Confidence: high, multiple concrete source incidents; corrected fixture performance is not product performance.

**L3 — Test the full evidence consumer, not only a strict helper.** Voldenites review rejected tracing wrappers that changed Node callable semantics and parsers that accepted only part of the actual traced run; fixing the helper did not fix the caller's omissions (S22–S24). Another review rejected a native session101 launch followed by session202 polls/terminal while the real admitted session had no terminal (S25–S26). Recommendation: bind launch, every poll, terminal, every traced phase and final consumer to one exact scope/candidate. Verifier: whole-run counterexamples with mixed supported/unsupported events, missing phases and mismatched session identities. Confidence: high for source-reviewed defects and corrections; no universal interception claim.

**L4 — Missing native accounting stays unknown through retries and success.** Competition records failed-call generation before parsing, HTTP200 nonterminal streams, absent terminal counters and dispatches whose usage record might never be written (L002/L008/L013/L026/L032). Work is missing21/296 session receipts. S04–S06 distinguish measured lower bounds, complete-native totals and separately proposed interval methods. Recommendation: start coverage from dispatch identities, retain original and retry costs/time, distinguish visible tokens from provider-native hidden reasoning, and never label partial cost exact. Verifier: dropped terminal receipt and failed parser with an observed dispatch, plus a fully measured positive request. Confidence: high; provider/transport root causes often remain unestablished.

**L5 — Same committed source plus later success does not prove a repair.** Competition L069 records accepted096 and rejected094 with equal clean committed tree/archive but different whole-working-file hashes; runtime and ignored-state causes remain unresolved. L063's isolated3/3 replay passes do not erase the original full-run failure. Recommendation: preserve original failures and compare source, full effective inputs, runtime, resource context and observer versions before causal attribution. Verifier: reuse identical source with controlled changed environment and distinguish outcome variation from code correction. Confidence: high for source identity claims as recorded; causal explanation unknown.

**L6 — Recovery begins with actual effects, ownership and unfinished obligations.** S08 describes byte-verified idempotent archival and conflicting/partial upload refusal; S40 describes partially completed repository setup; S02 records an unsafe duplicate attempt despite a broker preventing the second effect. Competition retains rejected working trees before reverting and archives resources before retirement (L016/L025/L033/L043/L047/L058/L060). Recommendation: reconcile destination state, admitted owner, operation identity, cumulative limits and original state before retry or rollback. Verifier: success-with-lost-response, stale-owner write and interruption before/after registration. Confidence: high for documented patterns; local protocols are cooperative unless an external enforcement boundary is observed.

**L7 — Observation, integrity, archival and acceptance are different claims.** Penny's archive contract excludes raw prompts/environment and exports closed schemas, historical provenance and explicit unavailable fields (S08). Its inspected DB has58,347 events and no bundle records, while Wired has historical acknowledgments. Neither fact proves current remote recoverability. Recommendation: use separate observation coverage, archive recoverability and outcome acceptance states; verify downloaded byte identity and independent reconstruction where required. Verifier: missing/altered acknowledged asset, interrupted unregistered spool and overlapping-history conflict. Confidence: high for local counts/contracts; external state unverified by this research run.

**L8 — Readiness and synthetic assurance cannot substitute for the intended product.** Factory's handoff pilot is **NOT RUN**: two setup diagnostics, no three natural compactions, no distinct-agent transfer, no read isolation and no winning state approach (S10–S11). Semantic-search explicitly retires standalone W11 gating and distinguishes portable framework documentation, narrow pilots and unfinished full release (S50). Commons/Voldenites synthetic DORA and Meertecha classifier tests have explicit limits (S15–S20/S30). Recommendation: perform workflow assurance during actual scoped work, keep setup/fixture/product/beneficiary evidence separate and block only the dependent claim. Verifier: a fixture pass must not close a missing real user journey or create an unnecessary prerequisite project. Confidence: high for current source distinctions.

**L9 — Keep live state in its owning system, durable decisions in records.** SVKG replaces self-referential pending-merge snapshots with live GitHub/Git reconciliation; failed fresh-review allocation remains an explicit limitation despite eventual merge (S29). Voldenites preserves protected-main rejection and later operator resolution without rewriting the failure (S21). Penny retires its scheduler in favor of explicitly initiated sessions (S09). Recommendation: preserve decisions/hashes/unfinished obligations, query live delivery state before consuming it, and never infer review independence from a merge or a second role label. Verifier: stale pending-merge record versus an already merged PR; unavailable reviewer capacity must stay unavailable. Confidence: high for documented cases; no live service query performed here.

**L10 — User-visible proof needs artifact identity and honest modality labels.** Every Game's cumulative footage distinguishes genuine model requests, fixture responses, offline replay, held frames, omitted waits, automated input and unavailable physical-controller/owner review (S33–S36). Penny binds human verdicts to exact recordings (S09). Meertecha keeps enjoyment/value unverified and UDOP leaves analyst-value review pending despite technical evidence (S30–S31). Recommendation: bind demos/reviews to exact asset digest and tested revision, state cuts/input modality, and preserve pending beneficiary judgment. Verifier: a new recording cannot inherit an old asset's verdict; automated software evidence cannot close hardware or user-value acceptance. Confidence: high for disclosed methods, no independent visual/user judgment supplied by this harvest.

**L11 — Knowledge reuse requires identity, uncertainty and correction preservation.** Classwork, atmospheric graph and Ashwake separate shared canonical concepts from learner plans, pin ontology/specification, reconcile synonyms/backlinks and require support for causal edges (S37–S39). Semantic-search separates extraction accuracy from retrieval on reviewed data, keeps related clips out of opposing splits and preserves corrections beyond rebuildable indexes (S14/S50). Recommendation: retain one canonical meaning with explicit source/revision and uncertainty; keep private learner/biography workspaces outside organizational reuse. Verifier: synonymous duplicate concept, stale provenance, unsupported causal join and index rebuild after correction. Confidence: high for source policy, effectiveness not measured here.

**L12 — Bound engineering controls to their actual trust and authority.** Atelier pins dependencies and bounds paths, profiles, collisions and failed outputs (S32); reactive_space uses authenticated sender/reducers and fails closed on policy errors (S43); cards separates deterministic engine from hosting, atomic plans and hidden-state presentation (S45). Voldenites requires helper/credential/bootstrap admission **before** public fixture acquisition and keeps cached builds, proof statements, axioms, native libraries and clean-source replay separate (S20/S27–S28). Recommendation: describe which layer enforces each claim, establish controls before the protected action and preserve assumptions. Verifier: valid allowed path plus traversal/symlink rejection, source-to-object drift, incomplete dependency replay and an unsafe action before its privacy gate. Confidence: high for documented requirements/defects; no current deployment or security certification inferred.

These are recommendations for separately governed current-organization changes. This task does not silently amend policy, approve a new evaluator or promote an experiment. Existing current controls may already implement some recommendations; compare exact mechanisms before proposing duplicate controls.
