- Exit Criterion: Ownership and prior effects are established before mutation; uncertain effects remain explicit, never fabricated

## Procedure

1. Start fresh from explicit organization/role instructions, open task/run/claim and last checkpoint/handoff. Read actual native status before assuming an old worker stopped.
2. Compare claimed state to filesystem hashes/artifacts, Git branch/index/worktree/remotes, PR/CI and journaled external operation identities/results. Unknown response is unknown effect; inspect destination before retry. Do not delete or interrupt another owner's resource.
3. If active ownership conflicts or destination effect cannot be resolved, block overlapping mutation and record exact uncertainty/next observation. Continue independent authorized work. If ownership is resolved, record claim transfer/re-admission with refreshed scope/approval/dependency/budget/context checks.
4. Resume verified partial work instead of replaying completed effects. Preserve failed attempts and cumulative consumption; retry only after diagnosis, at most twice per operation. New run/depth does not reset limits.
5. Cancellation stops new delegation, interrupts owned workers, checkpoints known effects/artifacts and reconciles results. Record canceled state with residual obligations; never imply effects were undone.
6. Persist structured handoff and exact next safe action. Verify a fresh replacement can resume solely from records; field completeness alone does not prove recovery. Archive only terminal inactive records after 90 days with intact identity/history.
