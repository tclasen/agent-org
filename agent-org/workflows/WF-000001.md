## Procedure

1. Capture original intent and classify before registration. A clarification/status response is conversation only; materially ambiguous system target requires clarification before mutation. Record explicit source/grant and exclusions.
2. For substantive work Coordinator allocates task/requirement identities, maps canonical sources to observable criteria and names accountable role. Cross-boundary intent gets independently scoped organization/project/integration children, not a blended write grant.
3. Planner reads sources and produces a revisioned plan with deliverables, paths/resources, dependency relations, capability/model rationale, verifier, budget and rollback. A plan alone grants no execution.
4. Resolve applicable organization/project authority and conditions. Check acyclic satisfied blocking dependencies, actual role discovery/tool support, cumulative resources, candidate/source freshness and no conflicting claim. Missing approval blocks dependent action.
5. Record ready/admission, create run/claim/context manifest and requested configuration before fresh native spawn. Keep interactive Coordinator and at most three workers. Follow WF-000002.
6. On changed scope/dependencies/requirements, record impact and replan/reapprove affected work; preserve all prior history.
