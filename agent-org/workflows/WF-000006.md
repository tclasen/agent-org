## Procedure

1. Obtain named project authority before enrollment or writes. Record canonical repository root/remote identity, owner/delegate, authoritative issue/spec/instructions, allowed commands/events/resources, exclusions, merge/deployment limits and overrides in a Markdown profile linking sources.
2. Preserve independent history/remotes and outer-index exclusions. Installation uses two labeled temporary repositories only, no old/ migration or live production enrollment. Missing authority leaves a proposal, not an enrolled grant.
3. Name each adapter source/destination, schema/version/identity/causal mapping, specific read/write/import grant, provenance/redaction and coverage gaps. No blanket integration permission, paid receiver, daemon or new runtime.
4. Decompose cross-boundary work per WF-000001. Snapshot organization/project protected surfaces. Independently test approved adapter positive/negative behavior and each system's requirements. Missing project/organization approval blocks respective mutation and parent acceptance.
5. Production metrics require explicit service/environment/classification/serving-threshold/recovery policy and canonical commit/build/artifact/deployment/failure/recovery links. Live service registry starts empty. Fixture 100% serving and 30-minute stabilization remain synthetic, never silently adopted as live policy.
6. Coordinator admits only enabled, deduplicated session/manual/native CI trigger occurrences with inherited authority and cumulative budget. Record mechanism/occurrence/source revision; duplicate/disabled occurrence does not execute. Verify linked PR/outcomes and update profile/acceptance through WF-000003.
